# Device Profit Analytics

MySQL-first manufacturing analytics for detecting equipment anomalies, reducing unplanned downtime, and quantifying profit impact.

## Why this project exists

Unplanned downtime and rising scrap rates quietly erode manufacturing profit. This project turns raw sensor logs into an auditable management report by answering four questions:

1. Which machines are high risk?
2. What operational anomalies drive the risk?
3. What is the root cause?
4. What is the estimated financial benefit of corrective action?

## Key features

- **SQL-first pipeline**: cleaning, risk scoring, root-cause analysis, and financial estimates run in MySQL.
- **Data governance**: source inventory, lineage, run logs, and a ten-check SQL quality gate.
- **Idempotent setup**: no destructive `DROP TABLE` statements in the default schema.
- **Reproducible demo data**: 86,400 deterministic sensor records across 20 machines and 30 days.
- **Business-ready reporting**: HTML management report with charts and quantified savings.
- **Open-source workflow**: tests, linting, CI, Docker MySQL, contributing guide, and MIT license.

## Quick start

```powershell
git clone https://github.com/polaris-Debug/device-profit-project.git
cd device-profit-project
npm install
Copy-Item .env.example .env
npm run generate-data
npm run analyze
Start-Process .\outputs\report.html
```

For Linux or macOS:

```bash
cp .env.example .env
npm run generate-data
npm run analyze
```

## Local MySQL with Docker

```bash
docker compose up -d mysql
```

Use these credentials in `.env`:

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=device_profit_password
DB_NAME=device_profit_analysis
```

## Pipeline

```text
Node.js generator
  -> raw_sensor_logs.csv
  -> MySQL raw_sensor_logs
  -> SQL cleaning
  -> SQL analysis
  -> SQL validation gate
  -> Node.js export
  -> HTML report
```

See [Architecture](docs/ARCHITECTURE.md), [Data model](docs/DATA_MODEL.md), and [Data dictionary](docs/DATA_DICTIONARY.md).

## Data source

The repository uses synthetic data generated by `analysis/generate_sensor_data.js`. It does not contain real factory, customer, or personal data. The source inventory and lineage tables document every table in the database.

To use real data, replace `data/raw_sensor_logs.csv` with an export that matches the documented schema, or modify `analysis/run_mysql_analysis.js` to ingest directly from your operational database.
